1. Stored Procedures with Error Handlers

Demonstrates stored procedure sp_record_attendance with condition handlers for duplicate keys and SQL exceptions:

CREATE PROCEDURE sp_record_attendance(
    IN p_student_id INT, IN p_course_id INT,
    IN p_date DATE, IN p_status VARCHAR(10),
    IN p_remarks VARCHAR(255), OUT p_result VARCHAR(50)
)
BEGIN
    DECLARE duplicate_entry CONDITION FOR 1062;
    DECLARE EXIT HANDLER FOR duplicate_entry
    BEGIN
        UPDATE attendance SET status = p_status, remarks = p_remarks
        WHERE student_id = p_student_id AND course_id = p_course_id 
          AND attendance_date = p_date;
        SET p_result = 'UPDATED_EXISTING';
    END;
    INSERT INTO attendance (student_id, course_id, attendance_date, status, remarks)
    VALUES (p_student_id, p_course_id, p_date, p_status, p_remarks);
    SET p_result = 'RECORDED_SUCCESS';
END;
2. Automated Calculation Triggers

Demonstrates BEFORE INSERT and BEFORE UPDATE triggers calculating total marks, percentage, and assigning grades:

CREATE TRIGGER trg_before_performance_insert
BEFORE INSERT ON performances
FOR EACH ROW
BEGIN
    SET NEW.total_marks = NEW.internal_marks + NEW.assignment_marks + NEW.exam_marks;
    SET NEW.percentage = ROUND(NEW.total_marks, 2);
    SET NEW.grade = fn_get_letter_grade(NEW.percentage);
    
    IF NEW.percentage < 50.00 THEN
        SET NEW.remarks = 'Needs Academic Improvement';
    ELSEIF NEW.percentage >= 85.00 THEN
        SET NEW.remarks = 'Excellent Academic Standing';
    ELSE
        SET NEW.remarks = 'Satisfactory Progress';
    END IF;
END;
Database Normalization Verification (1NF to 5NF) Normalized Schema

Requirement: Each attribute contains atomic (indivisible) values, and each record is identified by a Primary Key.

Fulfilled: Student records store single-valued attributes (e.g. register_number, email). Multiple attendance dates or exam scores are normalized into dedicated rows in child tables (attendance and performances), eliminating repeating groups.

Requirement: Must be in 1NF, and all non-key attributes must be fully functionally dependent on the entire primary key (no partial dependency on part of a composite key).

Fulfilled: All tables use surrogate single-column integer Primary Keys (student_id, course_id, performance_id). Non-key attributes depend on the full primary key.

Requirement: Must be in 2NF, and no non-key attribute is transitively dependent on the primary key ($X \rightarrow Y \rightarrow Z$).

Fulfilled: Department details (dept_name, dept_code) are extracted into their own table (departments). The students and courses tables only store foreign key dept_id, eliminating transitive dependencies.

BCNF: For every non-trivial functional dependency $X \rightarrow Y$, $X$ is a superkey.

4NF: No multi-valued dependencies ($A \twoheadrightarrow B$) exist. Student attendance and examination marks are decoupled into distinct independent relational paths.

5NF (Join Dependency Normal Form): Tables cannot be decomposed into smaller tables without loss of relational meaning.
